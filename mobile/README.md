# Мобильное приложение

Flutter-клиент тренажёра: онбординг, сессия тренировки, карточка вопроса с разбором и
экран уровня по темам.

## Первый запуск

В репозитории лежит только Dart-код (`lib/`, `test/`, `pubspec.yaml`). Платформенные
каталоги `android/` и `ios/` генерируются Flutter и в git не хранятся — создайте их один раз:

```bash
flutter create . --platforms=android,ios --project-name interview_trainer
```

Команда не трогает существующие `lib/` и `pubspec.yaml`. Дальше:

```bash
flutter pub get
```

```bash
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8000
```

`10.0.2.2` — это адрес хост-машины изнутри Android-эмулятора; он же стоит по умолчанию.
Для симулятора iOS и десктопа подойдёт `http://127.0.0.1:8000`, для реального телефона —
IP компьютера в локальной сети. Бэкенд должен быть поднят (`docker compose up -d` в корне).

## Структура

```
lib/
  core/
    config/     базовый URL API
    network/    dio-клиент, обновление токена, ошибки
    router/     go_router и охрана маршрутов по состоянию сессии
    storage/    токены в Keychain / EncryptedSharedPreferences
    theme/      тема
  domain/models/  модели ответа API
  data/repositories/  доступ к API
  presentation/
    auth/        вход и регистрация
    onboarding/  профессия → специализация → грейд
    practice/    сессия тренировки, карточка вопроса, разбор
    profile/     уровень по темам
```

Состояние — Riverpod: `sessionProvider` держит статус сессии, роутер по нему решает,
показать вход, онбординг или тренировку.

## Сборка под iOS

Локального Mac нет, поэтому iOS собирается в облачном macOS-раннере — workflow
`.github/workflows/mobile.yml`, job `ios`, `macos-latest`. Сейчас сборка идёт без подписи
(`--no-codesign`): она проверяет, что код компилируется под iOS. Для загрузки в App Store
понадобятся аккаунт Apple Developer и сертификаты в секретах репозитория.

Следствие для кода: любая новая зависимость обязана поддерживать iOS. Android-only пакеты
сломают сборку — проверяйте платформы на pub.dev перед добавлением.
