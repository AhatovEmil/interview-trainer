# Развёртывание

Что нужно до начала: сервер с Docker (2 ГБ памяти хватит), домен, A-запись
которого указывает на этот сервер, и открытые порты 80 и 443. Порт 80 нужен не
для трафика, а для проверки владения доменом при выпуске сертификата.

## Первый запуск

```bash
git clone https://github.com/AhatovEmil/interview-trainer.git && cd interview-trainer
```

```bash
cp .env.example .env
```

Дальше `.env` правится вручную. Обязательны четыре значения:

| Переменная | Что писать |
| --- | --- |
| `SECRET_KEY` | `python -c "import secrets; print(secrets.token_urlsafe(48))"` |
| `POSTGRES_PASSWORD` | длинный случайный пароль, не `trainer` |
| `API_DOMAIN` | домен, который указывает на этот сервер |
| `ACME_EMAIL` | почта для писем об истечении сертификата |

Приложение не стартует, если `SECRET_KEY` остался значением по умолчанию или
короче 32 байт — это проверка в коде, а не соглашение.

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

Первый запуск занимает пару минут: собирается образ, накатываются миграции,
загружается контент и выпускается сертификат. Проверка:

```bash
curl https://ваш-домен/health/ready
```

## Что поднимается

| Сервис | Наружу | Зачем |
| --- | --- | --- |
| `nginx` (образ Caddy) | 80, 443 | TLS, сертификат Let's Encrypt, проксирование |
| `api` | нет | FastAPI, миграции и сид на старте |
| `postgres` | нет | данные |
| `redis` | нет | ограничение частоты, кеш |
| `backup` | нет | ежедневный дамп базы в `./backups` |

Наружу смотрит только прокси. База и Redis доступны лишь из сети compose:
порты, открытые для локальной разработки, в боевом файле перекрыты.

## Сертификат

Caddy получает и продлевает его сам, никаких cron и certbot. Условия: домен
указывает сюда, порты 80 и 443 открыты, `ACME_EMAIL` задан. Сертификаты лежат
в томе `caddy_data` — при пересоздании контейнеров они переживают, повторный
выпуск не понадобится.

Если сертификат не выпускается, смотрите `docker compose logs nginx`: почти
всегда это либо не проросшая DNS-запись, либо закрытый 80-й порт.

## Резервные копии

Сервис `backup` раз в сутки снимает сжатый дамп в `./backups`, проверяет, что
файл читается, и удаляет копии старше `BACKUP_KEEP_DAYS` дней. Проверка
целостности здесь не для красоты: дамп, который не разжимается, надо
обнаруживать сейчас, а не в момент аварии.

Восстановление делается руками — это осознанное действие, а не автоматика:

```bash
gunzip -c backups/trainer-20260810-030000.sql.gz | docker compose exec -T postgres psql -U trainer -d trainer
```

**Копию, из которой ни разу не восстанавливались, копией считать нельзя.**
Разверните её на отдельной машине хотя бы раз, засеките время и запишите
результат. Пока это не сделано, резервное копирование существует только на
бумаге.

Каталог `./backups` лежит на том же диске, что и база. Это защищает от
ошибочного `DROP TABLE`, но не от отказа диска — настройте выгрузку копий на
внешнее хранилище.

## Обновление

```bash
git pull && docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

Миграции применяются на старте контейнера `api`, сид контента идемпотентен.
Простой — секунды на перезапуск. Перед обновлением с изменениями схемы
снимите копию вручную:

```bash
docker compose exec postgres pg_dump -U trainer --no-owner trainer | gzip > backups/before-upgrade.sql.gz
```

## Сборка приложения под этот сервер

Адрес API зашивается в приложение при сборке. Релизная сборка без него или с
адресом по `http` падает на старте — так сборка с адресом localhost не уедет
в магазин незамеченной.

```bash
flutter build appbundle --release --dart-define=API_BASE_URL=https://ваш-домен
```

В CI то же значение берётся из переменной репозитория `API_BASE_URL`.

## Что остаётся сделать руками

- выгрузка резервных копий за пределы сервера;
- мониторинг: сейчас есть только `/health/ready`, оповещений нет;
- обновление образов Postgres и Redis при выходе исправлений безопасности.
